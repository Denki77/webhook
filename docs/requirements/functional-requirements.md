# Functional Requirements

Функциональные требования и ожидаемое поведение системы.

## Состояния

### FR-001. Состояния события

Минимальный набор состояний события должен позволять отличить:

* событие, ожидающее доставки;
* событие в процессе доставки;
* успешно доставленное событие;
* событие с временной проблемой;
* событие, доставка которого окончательно прекращена;
* событие, не доставляемое из-за состояния подписки.

### FR-002. Состояния доставки

Ответ о состоянии доставки должен содержать:

* идентификатор события;
* родительский идентификатор события;
* тип события;
* время возникновения;
* состояние доставки;
* время доставки, если она состоялась;
* причину неуспешной доставки;
* актуальное состояние подписки.

## Деактивация подписки

### FR-003. Автоматическая деактивация подписки

Система должна автоматически перевести подписку в состояние `disabled`, если выполняются установленные критерии
продолжительной или систематической недоступности получателя.

### FR-004. Завершение накопленных доставок

При переводе подписки в состояние `disabled` все ожидающие доставки, относящиеся к этой подписке, должны быть
прекращены.

Для каждой прекращённой доставки должна быть зафиксирована причина: `subscription_disabled`.

### FR-005. Самостоятельное возобновление

Клиент должен иметь возможность запросить возобновление подписки, находящейся в состоянии `disabled`.

### FR-006. Проверка endpoint перед возобновлением

Перед переводом подписки в состояние `active` система должна проверить доступность endpoint.

Если проверка завершилась неуспешно, подписка остаётся в состоянии `disabled`, а клиенту возвращается причина отказа.

### FR-007. Возобновление без накопленной истории

После успешного возобновления подписка должна получать только события, возникшие после её перехода в состояние `active`.

Ранее прекращённые доставки не должны восстанавливаться или отправляться повторно.
