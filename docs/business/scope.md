# Project Scope

## В область проекта входит

### Каталог доступных событий

Бизнес определяет перечень событий, на которые могут подписываться внешние получатели.

Для каждого события должно быть понятно:

* что оно означает;
* при каких условиях возникает;
* кому оно может быть доступно;
* какие данные предоставляются получателю.

### Управление клиентскими подписками

Клиент может:

* подписаться на доступный тип событий;
* отказаться от подписки;
* временно приостановить получение событий;
* возобновить ранее приостановленную подписку;
* просматривать состояние своих подписок.

### Передача событий внешним получателям

События, на которые подписан клиент, должны быть переданы соответствующему получателю.

### Учёт результата доставки

Для каждой доставки должна сохраняться информация, необходимая для определения её результата.

### Предоставление информации клиенту

По запросу клиент должен иметь возможность получить:

* идентификатор события;
* тип события;
* время возникновения;
* текущее состояние доставки;
* время успешной доставки;
* причину неуспешной доставки;
* состояние подписки.

### Работа с проблемами получателя

Проект должен учитывать ситуации, когда клиент временно или постоянно не может принимать события.

Бизнес-процесс должен предусматривать:

* временное продолжение попыток доставки;
* прекращение попыток, если дальнейшая доставка не имеет смысла;
* приостановку доставки клиенту при продолжительных проблемах;
* сохранение причины изменения состояния доставки или подписки.

## За пределами проекта

В текущую область проекта не входят:

* создание клиентами произвольных типов событий;
* изменение клиентами содержания внутренних бизнес-событий;
* гарантирование успешной обработки события внутри системы клиента;
* управление внутренними бизнес-процессами клиента;
* исправление технических проблем на стороне клиента;
* предоставление клиенту доступа к внутренним системам компании;
* использование механизма доставки как универсального обмена произвольными сообщениями;
* определение бизнес-смысла событий без участия владельцев соответствующих бизнес-процессов.

## Граница ответственности

Ответственность проекта начинается с момента принятия события для внешней доставки и заканчивается фиксацией результата его передачи получателю.

Успешная передача события клиенту подтверждает, что получатель принял уведомление. Она не подтверждает, что клиент корректно выполнил дальнейшую внутреннюю обработку.

## Будущие расширения

В дальнейшем область проекта может быть расширена следующими возможностями:

* пользовательский кабинет управления доставками;
* аналитика по событиям и подпискам;
* расширенные отчёты;
* повторный запуск отдельных доставок по запросу;
* разные условия доставки для отдельных категорий клиентов;
* дополнительные способы уведомления помимо webhook.

Такие возможности не считаются обязательной частью первой версии без отдельного бизнес-решения.
